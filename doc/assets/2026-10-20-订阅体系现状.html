KOCARD · Subscription System

订阅体系现状

一套账号 · 两套平台会员 · 三种付费入口 · 一个独立积分钱包

基于 kocard-app（B/dev）与 kocard-pro-desktop（main）代码静态梳理 · 2026-10-20

已实现链路 异步回调 / 遗留链路 移动端专属 断点 / 不互通
01 · 身份

同一账号，不是同一份会员

两端都走 login_or_register，共享同一个 user_id；但 /user/info 按平台返回“该平台生效”的会员。桌面端固定上报 X-Platform=nas，iOS 内购不会自动解锁桌面。

02 · 等级

200 不等于 Pro

移动端 200 是体验档（枚举名 trial），桌面端 Pro 要求 status == 1 && level >= 300。同一账号在两端看到的等级和权益不一致。

03 · 执行

前端在拦，后端没拦

移动端只执行 5 项权益；桌面端由 Vue UI 拦截多目的地、多任务和免费额度，任务接口只查 owner。直接调 API 或改前端即可绕过，任务失败也不退额度。

04 · 数据

两套本地数据，一条旧链路

移动端 GRDB、桌面端 SQLite，任务不互通；MQTT 仍发往旧 .mac 平台，当前桌面端没有订阅，也没有设备身份。

05 · 积分

AI 积分是独立钱包

/wallet/* 不属于会员权益，目前只在移动端使用；AI 修图扣积分，AI 选图看 VIP。桌面端没有钱包，也没有 AI 入口。

06 · 商品

SKU 在服务端，不在代码里

两端商品都由 /api/v1/rights 下发；移动端只展示 level > 100 的商品。具体 SKU、价格、时长、是否自动续费，要以服务端配置和 App Store Connect 为准。

统一订阅真正要合并的不是价格表，而是三张表：权益定义（m_* / d_* / nas_*）、平台与设备身份、执行点（客户端还是后端）。这三层不统一，价格表怎么改都会在两端出现“同账号、不同待遇”。
